# DAG Generation Skill

## DAG structure

Use the following defaults for every generated DAG:

- `dag_id`: `{pipeline}_migration`
- `schedule_interval`: `"0 2 * * *"`
- `start_date`: `datetime(2026, 1, 1)`
- `catchup`: `False`
- `tags`: `["dtcm", "migration", "wave1"]`
- `owner`: `"dtcm-migration"`
- `email_on_failure`: `True`

## Operators

- Create one `SparkSubmitOperator` per converted PySpark file
- `task_id`: filename without the `.hql` extension, with hyphens replaced by underscores
- `application`: `s3://dtcm-artifacts/wave1/{pipeline}/{task_id}.py`
- `conn_id`: `"spark_default"`

## Retry logic by complexity

Set retries based on the complexity value from the assessment metadata:

- `SMALL`: `retries=1`
- `MEDIUM`: `retries=2`
- `LARGE` or `COMPLEX`: `retries=3`
- `retry_delay`: `timedelta(minutes=5)` for all tasks

## Task dependencies

Chain tasks in the same order the HQL files appear in the assessment metadata:

```
task1 >> task2 >> task3 ...
```

## Source

This DAG replaces the Control-M job chain that was exported via
`controlm_export_tool`. The linear dependency order is derived from that export.

### Full worked example

For pipeline `daily_revenue_agg` with 2 HQL files and complexity=MEDIUM:

```python
# Generated by convert_subagent — MWAA DAG
# Pipeline: daily_revenue_agg | Complexity: MEDIUM
# Replaces: Control-M job chain → Apache Airflow DAG

from datetime import datetime, timedelta
from airflow import DAG
from airflow.providers.apache.spark.operators.spark_submit import SparkSubmitOperator

default_args = {
    "owner":            "dtcm-migration",
    "depends_on_past":  False,
    "email_on_failure": True,
    "retries":          2,
    "retry_delay":      timedelta(minutes=5),
}

with DAG(
    dag_id="daily_revenue_agg_migration",
    default_args=default_args,
    schedule_interval="0 2 * * *",
    start_date=datetime(2026, 1, 1),
    catchup=False,
    tags=["dtcm", "migration", "wave1"],
) as dag:

    load_transactions = SparkSubmitOperator(
        task_id="load_transactions",
        application="s3://dtcm-artifacts/wave1/daily_revenue_agg/load_transactions.py",
        conn_id="spark_default",
        retries=2,
        dag=dag,
    )

    revenue_daily = SparkSubmitOperator(
        task_id="revenue_daily",
        application="s3://dtcm-artifacts/wave1/daily_revenue_agg/revenue_daily.py",
        conn_id="spark_default",
        retries=2,
        dag=dag,
    )

    load_transactions >> revenue_daily
```

### Filename → task_id rules

| HQL filename | task_id |
|---|---|
| `load_revenue.hql` | `load_revenue` |
| `compute-metrics.hql` | `compute_metrics` (hyphen → underscore) |
| `Update Daily.hql` | `update_daily` (space → underscore, lowercase) |

### What to watch for

- **Single file pipeline**: no `>>` dependency needed. Just one operator.
- **Files with no clear order**: use alphabetical order as fallback. Note in a DAG comment.
- **Invalid Python identifiers as task_ids**: strip special characters, replace with underscore.

## Artifact Packaging

### File naming conventions

| Source | Output |
|---|---|
| `{name}.hql` | `{name}.py` |
| `{pipeline}` | `{pipeline}_dag.py` |

All filenames: lowercase, hyphens and spaces replaced with underscores.

### S3 path structure

```
s3://dtcm-artifacts/wave1/{pipeline}/
  ├── {name}.py          ← one per converted HQL file
  └── {pipeline}_dag.py  ← the Airflow DAG
```

### Naming edge cases

| Original | Output |
|---|---|
| `Load Revenue.hql` | `load_revenue.py` |
| `compute-metrics.hql` | `compute-metrics.py` (hyphens preserved in filename) |
| `UPDATE_DAILY.hql` | `update_daily.py` |

### Required result fields

```json
{
  "pipeline":                "daily_revenue_agg",
  "conversion_status":       "SUCCESS",
  "generated_files":         ["load_transactions.py", "revenue_daily.py", "daily_revenue_agg_dag.py"],
  "artifact_path":           "s3://dtcm-artifacts/wave1/daily_revenue_agg/",
  "transformations_applied": 245
}
```

### Order of operations

1. Convert all HQL files → PySpark (`transform_hql_tool` per file)
2. Generate DAG (`generate_dag_tool`)
3. Upload artifacts (`s3_upload_tool` — currently stubbed)
4. Call `finish_conversion_tool`

If `s3_upload_tool` returns an error: include in result but do NOT halt. Note artifacts are local only.
